- Top-level Cleanup always names the exact Attached repository root and restores that registered worktree only when it is on local branch `main`, has a fixed current `HEAD`, and has no merge, rebase, cherry-pick, revert, bisect, or other sequencer state. A detached head, another branch, unresolved entry, nested repository change, or changed admission blocks before mutation.
- A predecessor-worktree cleanup request inside an already selected next-tag Baseline continues that Baseline's exact role retirement instead of selecting this standalone route. Patch exports, reusable cache/target, toolchains, and Established evidence remain inputs, not cleanup targets; no capacity question or raw-output cleanup is a prerequisite.
- Cleanup restores tracked source outside `build/docs` to that same `HEAD` and removes exact pre-inventoried ordinary non-ignored untracked files through GitCustody. It never moves the branch, fetches, resets remotely, rewrites history, commits, or infers ownership from Git classification.
- `build/docs` remains retained user input. Attached source restoration preserves every ignored path, including root AGENTS.override.md. The separate temporary retirement below consumes only declared helper temporaries; build/docs, distribution output, toolchains, reusable cache/target, packages, tasks/rust-suite-baselines.json and other supplied roots remain retained.
- After the native effects, re-read the branch and tip, require a clean tracked and ordinary non-ignored source postimage outside `build/docs`, and require the retained document and ignored-path inventories to be unchanged. CleanupComplete is unavailable on a partial postimage.
- After Attached restoration, invoke release-cleanup with the declared roots to retire drained temporary data. A separately supplied tag additionally selects ReleaseBoundaryRetirement below only on explicit current-user request; absent tag leaves tasks, notes and worktrees unchanged.

- Explicit release-cleanup holds CargoLock and requires all temporary producers and readers drained. It consumes all baseline, full and focused execution records and logs. Only tasks/rust-suite-baselines.json remains as baseline comparison facts; no archive, relocation or supplementary baseline record is retained.
- Preserve exports, packages, toolchains, reusable caches and target, build/docs, tasks and worktrees not selected for retirement. Tag-prev stays user-owned. After release-cleanup Pass and owner fold, product Cleanup inventories only regular numbered `.patch` files in the real `<ProjectScratchRoot>/fixup-handoff/<Tag>` child, unlinks verified unchanged entries, and removes only that empty child. Unknown content blocks CleanupComplete; every other root remains untouched.
- Schema and packaging still consume their outputs normally, and GitCustody owns covered worktrees. Explicit Cleanup validates the complete bounded RecordRoot, RuntimeTemporaryRoot and build/tmp inventory before removal; it never selects a shared parent or expands an unknown target.
- RecordRoot, build/tmp and RuntimeTemporaryRoot are disposable roots. Runtime defaults to PROJECT_RUNTIME_ROOT, not a host temporary-directory literal; explicit overrides select the effective root. Clear every immediate entry without name or directory-only whitelists and retain the roots. Runtime cannot overlap working or scratch. No removal root may overlap skill or permanent storage.
- The caller drains all producers and readers, including SILK, before Cleanup. CargoLock and recorded process-group absence protect test execution; do not inspect unrelated host processes. Reject nested mounts and symlinked roots. Recheck each entry, restore access only on private directories without following links, remove directories and unlink other entries, then require empty roots. Retry uses remaining native inventory, not a cleanup record.

- Baseline's fixed same-tag cleanup successor validates only the selected tag's established baseline after its execution owner has reaped and consumed the temporary attempt. Separately, a user-selected next-tag Baseline may retire the sole predecessor global topology only after product work replaced the sole task and either its exact canonical primary prefix matches predecessor Main or its Established zero-patch Main equals the official parent; neither path enters Attached restoration.
- Once the selected Baseline is Established, its cleanup also retires only its primary predecessor's lane-note working set through the same exact published-note comparison used by explicit retirement. Current notes and canonical source exports remain untouched. Missing predecessor drafts are already clean; unpublished nonempty notes remain protected, and cleanup retry consumes the established result without rerunning tests.
- Established-baseline cleanup reads an existing sealed current Result directly. After explicit Cleanup has consumed the execution set, it uses Established comparison facts without reconstructing records or rerunning tests. Zero coverage likewise needs no execution record. A present partial execution set still belongs to its execution owner.
- Direct release-cleanup resolves registered Main and verifies its exact committed source projection. It retires only a currently closed task selected explicitly by the user; artifact publication alone cannot authorize retirement.
- Revalidate Main, its exact closed Git terminal, ordered Units/Flat Patches/Child Patches, and private publication. TaskIndex names only that task with OtherTasks empty.
- Remove the completed task file and its published lane-notes working set, then publish an empty ActiveTask and OtherTasks while preserving OverallTask and the entire baseline collection. Interrupted removal consumes only that completed tag's native publication; any second or unindexed release task is an error.
- Before task retirement, validate only a regular root notes.md and canonical lane directories containing regular notes.md files. Every remaining nonempty draft at either level must equal its exported copy; empty unpublished files are removable. Unknown files, symlinks, and unpublished changes block removal. Recheck files before unlinking and remove only empty directories. Partial cleanup resumes from remaining files without a journal or recursive deletion of unknown content.
- Keep global Main, UpstreamBaseline, their refs for BuildInstall and the next Baseline. Interrupted cleanup repeats registered Main and native publication checks after task removal; only the next Baseline retires this topology before reusing its paths.
- An unfinished release retains its task, global roles, repair parents, source prefixes, lane notes, and unresolved patch contract. Prefix export retires nothing. Diagnostic records remain until replacement or explicit drained Cleanup; task replacement preserves custody before Baseline removes predecessor topology.
- Covered repair parents still leave through GitCustody's reader-bound convergence before lane verification or final publication. Cleanup never replaces that owner or force-removes an unexplained worktree.
- RunnerEnv normally consumes reaped scratch and non-test payloads through their owners. Explicit Cleanup may abandon an interrupted but proven-reaped full or focused execution after its owner has finished diagnosis. It never consumes a live producer. Baseline execution records and logs follow the same explicit cleanup rule. Only Established comparison facts survive.
- Baseline stops before replay after predecessor-topology retirement and selected-tag preparation. Direct Cleanup returns CleanupComplete only after its Attached restoration, drained temporary retirement and any explicitly selected task retirement; it performs no replay, build, installation, export, synchronization, or deployment. Roll retains the task at its selected stop so draft work may later grow.
- No cleanup record, progress ledger, compatibility reader, inferred liveness, or alternate command is added.
